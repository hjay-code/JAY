1. 设计模式分类
1.1. 创建型模式：描述如何创建对象；特点：将对象的创建和使用分离；实现：单例，原型，工厂，抽象工厂，建造者
1.2. 结构型模式：如何将类或对象按某种布局组成更大的结构；实现：代理，适配器，桥接，装饰，外观，享元，组合
1.3. 行为型模式：描述类或对象之间如何协作共同完成无法单独完成的任务，以及分配职责；
        实现：模板方法，策略，命令，职责链，状态，观察者，中介者，迭代器，访问者，备忘录，解释器
2. 软件设计原则 sdp：提高可维护性和可复用性，增加软件可扩展性和灵活性
2.1. 开闭原则：对扩展开放，对修改关闭；使用 接口 和 抽象类
2.2. 里氏代换原则 lsp：任何基类可以出现的地方，子类一定可以出现。子类可以扩展父类的功能，但是不能改变父类原有的功能，尽量不要重写父类的方法
2.3. 依赖倒转原则 dip：高层模块不应该依赖底层模块，两者都应该依赖抽象；抽象不应该依赖细节，细节应该依赖与抽象。算是开闭原则的一种实现
2.4. 接口隔离原则 isp：不应该被迫依赖于它不使用的方法，一个类对另一个类的依赖应该建立在最小的接口上
2.5. 迪米特法则 lod：最少知识原则；如果两个软件实体无须直接通信，那么就应该第三方转发调用，以降低类之间的耦合，提高模块的独立性
2.6. 合成复用原则：尽量先使用组合或者聚合等关联关系来实现，其次考虑继承关系
2.6.1. 继承复用：简单，易实现
2.6.1.1. 破坏了类的封装性，父类对子类是透明的（白箱复用）
2.6.1.2. 子类和父类耦合度高。父类的任何改变都会导致子类的变化，不利于类的扩展和维护
2.6.1.3. 限制了复用的灵活性。从父类继承而来的实现是静态的，在编译时已经定义，运行时不可能发生变化
2.6.2. 组合/聚合 复用：将已有对象纳入新对象中成为一部分

3. 创建者模式 create
3.1. 单例模式 single：最简单的设计模式之一，提供了一种创建对象的最佳方式；确保只有单个对象被创建
3.1.1. 饿汉式：类加载时创建单例对象
3.1.1.1. Singleton_1 静态成员变量方式
3.1.1.2. Singleton_2 静态代码块方式
3.1.2. 懒汉式：首次使用时创建 
3.1.2.1. Singleton_3：无锁，全局锁，双重检查机制
3.1.2.2. Singleton_4:静态内部类方式；最常用的方式，静态内部类不在因为外部类加载而加载，只有被调用时才会加载并初始化，且可以保证只被实例化一次和实例化顺序
3.1.3. 枚举式：线程安全且只会加载一次，并且是唯一一种不会被破坏的方式
3.1.3.1 属于饿汉式，不需要考虑内存的情况下首选
3.1.4. 单例模式的破坏：序列化，反射
3.1.4.1. 序列化：SingletonSerialize，破坏序列化单例：BrokenSingletonSerialize
3.1.4.2. 解决：SingletonSerializeResolve， BrokenSingletonSerializeResolve
3.1.4.3. 反射：SingletonReflect，破坏反射单例：BrokenSingletonReflect
3.1.4.4. 解决：SingletonReflectResolve，BrokenSingletonReflectResolve
3.1.5. JDK 中的RunTime 就是恶汉式单例模式
3.2. 工厂方法模式 factory
3.2.1. 简单工厂模式 simple ：不算一种设计模式，更像一种编程习惯
3.2.1.1. 分离了对象的创建和业务逻辑，避免了修改客户代码
3.2.1.2. 新增产品时需要修改工厂代码，违反了开闭原则
3.2.1.3. simple_static :静态模式简单工厂，算是一种优化，不用经常创建对象
3.2.2. 工厂方法模式 factory ：定义一个用于创建对象的接口，子类决定实例化哪个产品对象。使一个产品的实例化延迟到了工厂的子类中
3.2.2.1. 新增时不用修改原来的代码，保持了开闭原则
3.2.2.2. 新增时会增加大量代码，增加了系统的复杂度
3.2.3. 抽象工厂模式 factory_abstract ：为访问类提供一个创建一组相关或相互依赖对象的接口，且访问类无须指定所要产品的具体类就能得到同族的不同种类的产品
3.2.3.1. 保证了客户端始终使用同一个产品族中的对象
3.2.3.2. 新增产品时，所有的工厂类都需要修改
3.3. 模式扩展 config：简单工厂模式 + 配置文件
3.4. 原型模式 prototype ：用一个已经创建的实例对象，通过复制该对象来创建一个新对象
3.4.1. 拷贝：浅拷贝，深拷贝
3.4.1.1. 浅拷贝：对于非基本类型，浅拷贝仍然只想原有对象的内存地址；Object 提供了clone 方法实现浅拷贝
3.4.1.2. 深拷贝：在内存开辟一个新地址来存放原有对象的数据；Cloneable 接口来实现深拷贝；使用负载对象的创建或者对性能和安全要求比较高的场景
3.4.1.3. 深拷贝时，如果成员变量是对象，那么就可以使用序列化来进行深拷贝，会方便很多，但是会有更大的性能开销和其他问题
3.5. 建造者模式 builder ：将一个复杂对象的构建与表示分离
3.5.1. 封装性和稳定性很好，客户端不必了解细节，可以创建不同的产品对象；容易扩展，符合开闭原则
3.5.2. 适合有较多共同点的产品
3.5.3. 场景：对象较为复杂，由多个部件构成且部件面临复杂的变化但建造顺序是稳定的；创建复杂对象的算法独立于该对象的组成部分以及装配方式，即产品的构建过程和最终表示是独立的
3.5.4. 模式扩展 builder_ex：使用 Builder 来自定义组件的构建顺序和组成。代码使用起来更加的方便
