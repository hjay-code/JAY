1. FLuxDemo
1.1. 数据流：元素（N个） + 信号（1个，正常/异常）, 不消费就不会 使用/占用 内存，SignalType 信号枚举类
1.2. 一个 流 可以被多个消费，每次消费的都是一样的：广播模式
1.3. 基于事件感知，生产者 doOnXXX 当发生事件时，触发回调，不能改变 元素/信号
1.4. 中间操作 的 链式调用 每次都会生成一个新的流：整流，每个 操作 都是对 上一个操作 生成的流进行操作
1.5. 消费者 和 生产者 在 流 中使用 事件 进行通信
1.6. Flux 是 生产者；可以不指定 消费者 的订阅，代表流 开始运行；也可以指定多种消费者，代表不同信号执行不同的操作
1.7. 消费者 hookOnXXX 事件回调方法，监听事件， 提供了 BaseSubscriber 默认消费者
1.8. 生产者 onXXX 事件监听，当发生某个事件时，执行，可以改变 元素/信号
1.9. 消费者 可以 随时 取消 订阅， 实现 Disposable 接口
1.10. 生产者 可以 添加缓冲区 buffer(N) ，可以指定缓冲区的大小，每次发送缓冲区的全部数据 List<Object>
1.11. 生产者可以使用 handle 自定义处理消息逻辑
1.12. reactor 默认是在 main 方法生成，发布，操作 流
1.13. 使用 Schedulers 来进行异步操作，生产者和消费者都可以异步


2. FluxTest 流的常用操作
2.1. filter，flatMap，concatMap，transform，empty，merge，zip，error，retryAndTimeout，sinks，block，parallel，context
2.2. 生产者 发送 异常/结束 信号后，所有的 消费者 都能监听到
2.3. Flux 默认是多播，非重放模式，使用cache 保存缓存元素，实现重放功能
2.4. 阻塞式api也是一种 消费者 的实现方式
2.5. ThreadLocal 只能在线程固定中使用， 在响应式中无法使用，
2.6. 数据流中共享数据使用 Context API，从下游反向传播到上游；下游看不到Context，只有上游能看到，且初始化后不可变
